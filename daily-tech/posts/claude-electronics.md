# 今日科技长文：Claude 已经能从一句话设计出真正能工作的电子产品，AI 正在跨越软件与物理世界的边界

今天推荐 **Anthropic Science 团队于 2026 年 11 月 9 日发表的《Testing Claude on real-world electronics design》**，中文可译为《在真实电子硬件设计中测试 Claude》。这篇文章由 Anthropic 的 Mike Cretella、Connor Jennings、Brent Yi，以及 Diode Computers 的 Craig Chen 等工程师参与完成。**全文免费公开**，包含实际制造的硬件照片、四层 PCB 布线图、设计修改案例和模型评测数据。结合图片及技术背景，适合花约 15–20 分钟深入阅读。

真正令人印象深刻的并不是 AI 画出了 PCB，而是它能够发现设计中的物理冲突，重新组织布线，编写自己的 CAD 辅助算法，还能考虑声音共振、供电限制和工厂制造条件。

这标志着 AI Agent 的一个重要变化：它不再只是处理数字文件，而开始协调软件、几何、电气和制造约束，尝试生产现实世界中能够使用的物体。

## 为什么硬件设计远比生成代码困难？

过去一年，Coding Agent 已经证明自己能够独立修改大量代码。但电子硬件设计与软件开发之间存在一项根本差异。

软件代码修改以后，通常可以立即重新运行测试。

而 PCB 设计一旦交给工厂制造，铜线位置、焊盘、过孔、芯片引脚和电路板形状就成为真实的物理结构。

如果工程师发现某条线路与其他信号发生冲突，或者连接器位置错误，可能需要重新设计并制造电路板。

这比修改一行代码昂贵得多。

更复杂的是，硬件设计涉及多个彼此关联的专业领域。

一块 PCB 的原理图必须在电气上成立，但正确的原理图并不意味着 PCB 布局正确。

元器件必须按照合理位置放置，电源和高速信号线路需要满足不同要求，最终制造工艺也必须能够实现这些几何结构。

此外，电路板还需要安装进外壳。工程师必须确保螺丝、接口和其他部件不会产生机械冲突。

固件又需要与实际选择的芯片和引脚分配相匹配。

因此，一个看似简单的消费电子产品，实际上是多个工程约束共同作用的结果。

Anthropic 在 2025 年就开始与 Diode Computers 合作，让 Claude 学习读取芯片 Datasheet（数据手册），判断一颗芯片正常工作需要哪些外围元件。

当时的模型已经能提供一些有帮助的电路设计建议，却经常无法形成完整可用的 PCB。

例如，模型可能知道电源旁边应该使用去耦电容，但不能正确决定它应该放在哪里。

又或者它能完成大部分布线，却在最后几条连接上陷入死局。

**这次进步的关键，不是 Claude 突然学会了更多电子学术语，而是它能够在多个现实约束之间持续推理，并修正自己的决策。** <Cite ref="turn341006view0"/>

## 从一句话到真正的硬件：Claude 究竟独立完成了哪些工作？

研究团队给 Claude 提供的是简短的产品描述，而不是完整设计图。

例如，会议扬声器的需求大致是：设计一个通过 USB-C 连接电脑的圆形设备，包含麦克风、扬声器和蓝牙功能，并使用集成在 PCB 上的天线。

这种描述确定了产品的大致功能，却没有指定芯片型号、原理图、PCB 形状、铜线布局或具体外壳结构。

Claude 需要把这些要求转化成实际工程方案。

根据 Anthropic 的披露，模型完成了功能规格、电路原理图、元件选型、PCB 元件布局、铜线连接、可 3D 打印外壳、固件，以及供制造使用的物料清单（Bill of Materials，BOM）。

这已经覆盖了一次电子产品原型开发中的大部分设计环节。

但它没有亲自操作工厂设备。Diode 的工程师仍然负责实体制造、组装和运行测试。

研究团队表示，三款设备都能正常工作。其中会议扬声器经过数周使用，仍保持功能正常。

不过，这里的成功必须精确理解。

**“电路不需要修改就能让原型正常运行”，不等于“产品已经通过完整电气、可靠性和安全验证”。**

原型能够启动并执行预期功能，只是迈向商业产品的一部分。

真正量产之前，还需要测试天线、电磁兼容、热性能、长期可靠性，以及不同制造批次之间的一致性。

这些工作并未在本次研究中全部完成。<Cite ref="turn101057search0"/>

## Claude 首先解决了一个传统 AI 很难做好的问题：复杂空间几何推理

PCB 设计有点像在一座高度拥挤的多层城市里规划道路。

芯片、连接器和其他元器件相当于建筑。

铜线相当于道路。

而不同信号对道路的长度、宽度、距离和干扰有不同要求。

普通低速控制信号可能允许比较灵活的走线方式。

但高速差分信号通常需要精确控制线宽、间距和路径长度。

如果一对差分线长度差异过大，信号到达时间可能不同，从而影响信号完整性。

因此，工程师经常需要设计蛇形走线，让较短线路延长到与另一条线路接近。

Claude 在家庭语音助手 PCB 的设计过程中，优先处理 USB 和 Ethernet 连接。

它没有简单地寻找两点之间最短的路径，而是按照差分信号的约束，考虑成对线路的长度和相对距离。

它还调整部分线路的形状，让相关信号尽量同步到达。

对于电源部分，模型则考虑如何安排元件和供电路径，以减少不必要的损耗。

这种能力区别于纯粹的几何绘图。

一个布局在视觉上可能很整洁，却不一定符合电气要求。

因此，Claude 需要把几何空间与电气属性结合考虑。

这正是此前模型很容易失败的地方：**它们能够识别元件，却无法稳定处理元件之间复杂的物理关系。** <Cite ref="turn341006view0"/>

## 为什么四层 PCB 的触摸控制区，反而成了 Claude 最出色的案例之一？

会议扬声器使用四层铜结构。

它包含一个触摸控制区域。

触摸控制依赖 PCB 上的铜电极检测手指带来的电容变化。

但这带来了复杂的布线要求。

如果铜线需要从一个 PCB 层转移到另一个层，通常需要使用 Via，也就是过孔。

在触摸电极附近增加过孔，可能干扰电极形状和设计要求。

因此，模型必须尽量避免让相关铜线在触摸控制区域交叉，或者通过额外过孔换层。

Claude 最初也遇到了布局拥挤的问题。

但它没有只尝试在现有布局里挤入更多线路。

它选择重新分配两颗芯片上可以交换的信号引脚。

这样一来，原本需要交叉的线路就能重新安排，不必使用额外的换层连接。

当 PCB 背面的一角仍然过于拥挤时，Claude 进一步修改部分信号与引脚的对应关系，并重新设计整片局部区域。

这一行为很重要。

因为**它不是单纯执行布线算法，而是在改变上游设计决策，为下游几何问题创造新的解空间。**

它还为蓝牙 PCB 天线保留了周围的铜箔禁布区域。

这是因为附近的导电金属可能改变天线电磁场分布，影响射频性能。

这些细节说明，模型并不是只追求把线路全部连接起来，而是开始考虑它们连接以后是否能够正常工作。<Cite ref="turn341006view0"/>

## 比会画 PCB 更重要的是：Claude 知道什么时候应该推倒重来

研究中出现了一个非常具有代表性的行为变化。

Anthropic 表示，早期模型经常能够完成约 95% 的 PCB 设计，却始终无法处理最后几条线路。

这种情况在硬件工程中尤其麻烦。

一块完成 95% 布线的 PCB，如果剩余连接无法实现，就可能完全不能制造。

而且，前面的设计越复杂，工程师越容易陷入局部修补。

新版 Claude 表现出不同的工作方式。

在设计家庭语音助手时，它发现麦克风附近的线路布局存在潜在问题。

部分供电铜线绕过麦克风底部的接地区域，另有连接穿越了不理想的位置。

这些线路可能满足基础间距规则，但从麦克风附近的信号与接地布局来看，并不理想。

于是 Claude 主动删除部分已有走线，并重新规划。

它在整个 PCB 设计过程中多次重复这种操作，而不是不断累加临时修补。

这体现了一个与 Agent 成熟度密切相关的特征：

**模型不仅需要知道下一步做什么，还需要判断此前的工作是否值得保留。**

对于复杂工程任务，这种能力可能非常重要。

因为很多真正困难的问题，并不是缺少下一步操作，而是早期决策已经把整个设计带入了无法完成的状态。

一个能够主动重新规划的 Agent，可能远比一个只会不断执行后续步骤的 Agent 更有实际价值。<Cite ref="turn341006view0"/>

## Claude 甚至认为现有工具太麻烦，于是自己写了一个新的 PCB 布线器

这是我认为整篇文章最有意思的技术细节。

家庭语音助手拥有一个 100 Pin 连接器，需要引出大量线路。

Claude 最初使用 Diode 提供的设计工具，通过 KiCad 的内置布线功能执行任务。

KiCad 是一款广泛使用的开源电子设计自动化（EDA）软件。

但当连接器涉及大量较长的铜线时，逐条指挥 KiCad 画线的方式显得效率很低。

模型每处理一条线路，都需要指定起点和终点。

对于几十条复杂线路，这会产生大量重复操作。

于是 Claude 改变方法。

它编写了一套自己的网格搜索布线算法，将 PCB 平面划分为网格，并在约束条件下寻找可用的连接路径。

根据 Anthropic 的披露，Claude 在约半小时内完成了这个工具。

新算法可以在大约一秒内，为一条较长的线路寻找路径。

模型随后发现，一条音频时钟信号线距离 Ethernet 线路过近。

它又进一步修改自己的布线器，提高敏感线路附近的避让距离。

这个案例展示了一种比单纯使用工具更高级的行为：

**当已有工具不适合当前任务时，Agent 可以先编写新的工具，再使用它完成原本的工程目标。**

不过，这仍然是研究团队披露的具体案例，不代表这个临时生成的布线算法已经达到商业 EDA 软件在所有场景中的可靠性和性能水平。<Cite ref="turn341006view0"/>

## 电路正确还不够：Claude 必须理解产品的声学和机械结构

硬件设计的另一个困难，是不同专业领域的决策会相互影响。

例如，电路板上一个开关的位置，可能决定外壳内部需要保留多少空间。

外壳的一处开孔，又可能改变麦克风的声学表现。

在会议扬声器设计中，Claude 发现 PCB 无法直接垂直放入外壳。

因为静音开关会与外壳后壁发生碰撞。

它没有立即认定 PCB 或外壳必须重新设计。

相反，模型检查了不同装配姿态，发现如果将 PCB 倾斜约 **25°**，就可以避开冲突，再将电路板旋转到最终安装位置。

随后，它把这种安装方式加入装配说明。

这是一种典型的真实工程思维：解决问题不一定需要修改产品本身，也可以改变装配过程。

另一个案例来自家庭语音助手的麦克风开孔。

Claude 估计，原先约 **25 毫米**长的麦克风声音通道，会在约 **3.4 kHz** 附近产生声学共振。

这个频率处于语音相关频段，可能影响声音拾取效果。

于是模型重新考虑了外壳形状。

它把外壳改为前低后高的楔形结构，将麦克风声音通道缩短到约 **10 毫米**。

按照其设计估算，共振频率相应升高到约 **8.9 kHz**，远离原先较敏感的主要语音频段。

这里的数字是模型设计过程中的声学估算，不是已经经过完整实验室声学验证的测量结果。

但这个案例说明了一个关键变化。

**模型能够把外观设计、机械结构和物理性能联系起来，而不是只生成一个看起来漂亮的外壳。** <Cite ref="turn341006view0"/>

## Claude 还把供电约束传递到了固件里

电子产品中的软件与硬件不是完全独立的。

例如，设备上的 LED 灯光会消耗电流。

如果扬声器、电路和 LED 同时以较高功率运行，系统可能超过设计允许的电流限制。

因此，模型不仅需要设计供电电路，还需要保证固件的运行方式符合硬件限制。

在会议扬声器中，Claude 编写了控制 LED 灯环的固件。

当音频输出音量增加时，模型让 LED 亮度相应降低。

这样可以帮助设备避免超过设计中的电流预算。

这个细节看起来很小，却很有实际意义。

对于真正的嵌入式系统，硬件约束不应该只留在电路设计文件里。

它还应该影响设备运行时的软件行为。

另一个案例是手持电子宠物的电池充电电路。

Diode 工程师曾询问模型，如果设备没有安装电池，是否仍然能够使用 USB 电源运行。

Claude 查阅了充电芯片的数据手册，判断设备可以运行，但预测充电指示灯可能闪烁，因为充电管理电路会不断尝试为原本由电池承担的节点上的小电容充电。

这个例子再次说明模型能够利用元器件的具体规格进行推理。

但原文没有明确证明闪灯预测已经通过实测验证，因此不能把它当作确认的实验结果。<Cite ref="turn101057search0"/>

## 从原型到制造，最容易被低估的是 DFM

如果 Claude 只能设计出在仿真环境中成立的 PCB，它依然无法真正替代任何实际的工程工作。

因为工厂存在具体制造限制。

例如，铜线不能无限细。

相邻焊盘必须满足一定的间距要求。

阻焊层（Solder Mask）不能任意形成极窄的孤立结构。

而元器件也必须能够通过供应链实际采购。

因此，设计人员通常需要进行 Design for Manufacturing（DFM，可制造性设计检查）。

Anthropic 表示，Claude 会自己执行相关检查，并判断哪些警告需要修复，哪些属于可以合理忽略的误报。

在家庭语音助手 PCB 上，自动化检查发现六处阻焊层开口附近存在过窄结构，不适合制造。

Claude 通过修改阻焊层开口的几何形状解决问题，无须重新移动元器件。

另一个检查则将两个接地区域之间的连接标记为错误。

但 Claude 判断这项连接本身就是设计中有意安排的，因此没有不必要地修改它。

这里的关键不在于 AI 能否通过某个规则检查。

而在于它能够区分**几何制造违规、真实电路问题和自动化检测误报**。

Diode 最终根据 Claude 输出的文件制造了全部三块电路板。

合作团队表示，整个制造过程没有出现需要设计方反复修改电路的情况。

对于普通电子产品原型开发，这是一项具有实际意义的结果。

但它仍然只是三个经过选择的原型项目，不代表任意复杂度的 PCB 都能实现同样的首次制造成功率。<Cite ref="turn341006view0"/>

PCB Gym 会从已有 PCB 设计中移除布局，让模型重新放置元器件并建立铜线连接。

这个测试更接近 PCB 设计中的空间组织与布线工作，但它属于 Diode 的内部 Benchmark。

因此，外部研究人员尚不能仅凭这组分数，完整判断其测试集如何选取、是否具有足够代表性，以及与其他模型的真实工程表现如何比较。

另一项 Benchmark 是公开的 BenchCAD 2.1。

它涵盖根据工程图和渲染图重建 3D 零件、机械装配体与 PCB 等任务。

Anthropic 报告 Claude Fable 5.2 达到 **83.5%**，而此前 Fable 5.1 的得分为 **44.4%**。

不过，进一步查看 BenchCAD 官方说明，会发现一个重要的方法学细节。

Fable 5.2 的 83.5% 是在允许工具辅助的配置下取得的；同一模型使用标准配置的得分约为 **75.4%**。

因此，不同工具环境和评测执行方式会改变成绩，不能混用不同版本或者不同执行条件的数据来证明模型具有某种绝对领先优势。<Cite ref="turn341006search2"/>

总体而言，这些 Benchmark 支持的结论是：Claude 在几何和工程工具任务上的能力显著进步。

但真实电子设计能力，还需要通过更多不同复杂度、独立复现的工程项目验证。

## 为什么这项研究不能被理解为 AI 已经可以取代硬件工程师？

Anthropic 在原文末尾明确指出了研究局限。

目前三款设备都只是原型。

它们没有完成完整的电气验证。

天线尚未经过系统调校。

长期热性能与可靠性尚未验证。

相关产品也没有完成商业认证。

而且，它们本身并不是面向大规模生产设计的产品。

这非常重要。

例如，一款 Bluetooth 设备在实验室里能够建立连接，并不代表它满足正式射频认证要求。

一块 PCB 在室温下能够稳定运行，也不代表它在极端温度、静电放电或长期运行条件下能够保持可靠性。

同样，一款外壳可以通过 3D 打印制作，也不意味着它能直接采用注塑工艺大规模生产。

注塑制造需要考虑模具分型、拔模斜度、材料收缩和装配公差等问题。

这些都可能要求重新设计结构。

更重要的是，Claude 目前还没有直接连接所有物理测试和制造设备。

因此，人类工程师仍然需要负责实体装配、测量与判断。

我认为这份研究已经证明了一种很有价值的原型开发能力，但还没有证明完整的、无人参与的商业产品研发能力。<Cite ref="turn101057search0"/>

## OpenAI 也在做类似研究，这意味着什么？

值得补充的是，OpenAI 在 2026 年 11 月 3 日发表了《Accelerating Engineering for the Physical World》，展示了 AI 参与电子、机械和跨专业工程设计的工作。

该研究使用 GPT-6 Astra 设计了一款可以与 Codex 交互的实体设备，覆盖外观、外壳、电路板及软件集成。

OpenAI 表示，两名团队成员在不到一周的兼职项目时间里完成了主要设计工作，合同制造商在一个月内制作了少量原型。

但 OpenAI 同时承认，模型在制造约束、公差与装配细节上仍然存在不足，需要经过多轮人工审核和修改。

OpenAI 还介绍了在赛车工程和汽车设计中的应用，包括将扫描得到的零件转成可编辑 CAD 模型，以及借助仿真探索车辆空气动力学方案。

这些案例与 Anthropic 的结果相互印证，说明前沿 AI 公司正在将 Agent 从纯软件任务推进到真实工程工作流。

但两家公司采用的任务、模型、工具和人工参与程度不同，不能凭原型数量或演示结果直接判断谁的硬件工程能力更强。<Cite ref="turn101057view0"/>

## 我的进一步判断：AI 可能正在把硬件创业最昂贵的早期环节变得更便宜

下面是我的独立分析，不属于 Anthropic 原文已经通过经济学实验证明的结论。

我认为这项研究最深远的商业价值，可能并不是让大型电子企业减少多少 PCB 工程师，而是降低设计原型的成本。

过去，一家软件创业公司可以相对迅速地做出 MVP（最小可行产品）。

但硬件创业通常需要找到电子工程师、机械工程师、嵌入式软件工程师，还要协调采购、打样和测试。

团队即使只想验证一个很简单的产品想法，也可能需要投入大量专业人员时间。

如果 Agent 能够承担初步原理图、PCB 布局、外壳设计、固件和制造检查，那么早期创业者可能以更少的人力完成更多候选方案。

这并不意味着实体制造成本会消失。

PCB 仍然需要生产。

元器件仍然需要购买。

测试仍然需要设备。

但原型设计的时间和专业劳动成本如果显著下降，就可能改变哪些产品值得尝试。

例如，过去一个只服务几千名专业用户的电子设备，可能因为工程开发成本太高而不值得生产。

未来，如果初始工程成本足够低，某些小众硬件产品可能获得新的商业可行性。

这与过去软件开发工具普及后，越来越多小型软件团队能够独立开发产品的过程有些相似。

但硬件开发不会完全复制软件行业，因为真实制造、库存和售后服务仍然具有固定成本。

## 对 EDA、工业软件和半导体行业的影响

我认为未来 EDA 市场值得关注一个结构性变化：AI Agent 可能逐渐成为现有工程软件的重要使用者，而不只是用户界面上的辅助聊天工具。

传统 EDA 软件提供原理图编辑、PCB 布局、规则检查、仿真和制造文件生成。

工程师负责决定如何使用这些工具。

但在 Anthropic 的案例中，Claude 已经能够自己选择工具、调整设计、执行检查，并在现有工具不够高效时编写补充算法。

这意味着未来 EDA 的交互模式可能发生变化。

工程师仍然负责需求与技术判断，但越来越多的实际操作可能由 Agent 执行。

对于 Cadence、Synopsys、Siemens EDA、Altium 等厂商，我认为长期机会不只是把自然语言功能添加到现有产品，而是把电路设计、仿真、验证与制造规则变成 AI 可以可靠调用的工程平台。

但需要区分消费电子 PCB 设计与先进集成电路设计。

PCB 布局并不等于芯片内部的逻辑综合、物理设计、时序收敛和签核验证。

这些领域的约束更加复杂，不能直接由本次实验推断同等程度的自动化已经实现。

同时，Agent 如果能够自行编写特定的小型工程工具，也可能对部分功能简单、依靠人工操作收费的软件产生竞争压力。

因此，未来真正有价值的软件能力，可能越来越集中在高质量物理模型、可信验证、复杂工程数据与制造生态整合上，而不只是操作界面。

## 更深的意义：AI 的下一阶段，不是生成更多设计图，而是缩短从想法到真实物体的距离

我认为《Testing Claude on real-world electronics design》最值得记住的，并不是 69% 的 PCB Gym 成绩，也不是三款小型电子产品。

而是它揭示了 AI Agent 正在跨越的一个关键门槛：从只操作数字信息，走向能够同时处理多种真实物理约束的工程工作。

当 AI 修改软件代码时，世界通常会通过编译器、测试和运行时行为给它反馈。现在，模型开始能够把电路、机械、声学、电源和制造规则组织成一个相互关联的工程过程。这意味着 Agent 的价值不再只是减少重复操作，还可能来自更快地探索跨专业设计方案。

对科技和投资而言，这种变化如果继续发展，可能让硬件原型、自动化实验室、机器人系统和工业产品开发都出现新的生产率提升。但这项技术距离完全自主的大规模制造仍有明显距离，真正的商业优势将取决于谁能把模型生成的设计，与仿真、真实测量、认证和制造反馈连接成可靠的闭环。

**当一名工程师能够用自然语言描述产品，让 AI 自动生成设计，再从真实原型的测试结果中持续改进，硬件创新的基本成本结构才可能发生更深刻的变化。**

我认为这比单纯讨论哪家模型又提高了多少编程得分更加值得长期追踪。因为它预示的不是 AI 仅仅加快软件开发，而是人类创造真实物理产品的方式，也可能开始被 AI 重塑。
