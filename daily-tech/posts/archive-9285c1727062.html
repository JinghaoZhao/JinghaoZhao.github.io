今日科技长文：Anthropic 不只是想让 Claude 操作软件，它开始给 AI 建一套“USB 接口”，直接连接实验室和工厂

今天推荐 Anthropic 于 2026 年 8 月 27 日发布的长文 《Previewing the Model Hardware Standard》。这是 Anthropic 官方的一手技术文章，目前免费公开阅读。文章介绍了一个新标准 Model Hardware Standard，MHS：它试图为 AI agent 操作显微镜、液体处理器、机械臂、激光器、PCR 仪器乃至量子计算机设备建立统一接口。阅读 Anthropic 原文 Anthropic

我今天选它，是因为过去几天我们连续讨论了自动科研、synthetic environments 和 AI researcher，而 MHS 正好补上了那套逻辑里最难自动化的一环：真实世界实验。模型已经越来越会提出 hypothesis、写代码、分析数据，真正拖慢 scientific loop 的往往不是“想不到下一步做什么”，而是实验室里的仪器来自不同厂商、接口互不兼容，需要研究人员手工搬样品、盯设备、排故障。Anthropic 现在做的不是另一颗机器人“大脑”，而是试图标准化 AI 与物理设备之间的控制层。如果这个方向成立，MCP 把软件世界变成 agent 可调用工具之后，MHS 可能尝试把一部分物理世界也变成同样可调用的工具。Anthropic

MHS 要解决的第一个问题其实非常“无聊”：实验室设备根本不会彼此说话

Anthropic 开篇描述了一个长期存在于科研和制造业里的现实问题。实验室里即使已经有大量自动化设备，每台机器往往仍然拥有自己的 programming interface、数据格式和 vendor software。如果要让显微镜、液体处理器、机械臂、plate reader 等设备协同工作，通常需要专业工程师逐个编写 glue code。完整集成往往需要数周甚至数月。Anthropic

更麻烦的是，把几台机器“接起来”之后，还没有一个统一办法让 AI agent 知道这些设备能做什么、当前是什么状态，以及哪些操作绝对不能执行。

MHS 试图把这两件事同时标准化。

它首先定义一个统一 driver layer。设备向上暴露非常简单的 primitive，例如 read 可以表示“读取温度”，write 可以表示“把温度设置为某个值”。不同厂商下面到底用什么 API 或控制系统，由 driver 自己负责转换。Anthropic

同时，每台设备会通过标准格式描述自己的 capabilities 和 state。Agent 因而不需要先为某个 Thermo Fisher 仪器学一套接口、再为另一个 Tecan 设备学另一套接口，而是通过同一种抽象访问它们。

Anthropic 进一步加入了自然语言 tags。这里存的不是纯软件 API 能表达的信息，而是大量过去存在于说明书或者实验员脑子里的 tacit knowledge，例如机械臂有多重、运动范围是多少、设备可以调哪些参数，以及必须执行哪些安全限制。系统再利用这些信息自动生成一份 reference file，让 agent 在第一次看到设备时就知道怎样使用它。Anthropic

这一层非常重要，因为真正的物理世界和软件不同。调用一个错误 API 最坏可能返回 error；让机械臂以错误方向运动、让激光功率过高或者让液体处理器发生碰撞，可能直接损坏实验和设备。

所以 Anthropic 并没有把安全完全交给模型自己“判断”。MHS 的思路是在设备层预先声明和执行一些 hard safety limits。

MCP 与 MHS 并不是同一个东西：一个连接软件，一个连接机器

Anthropic 明确说，MHS 是 model-agnostic 的，并不要求必须使用 Claude。任何 agent harness 理论上都可以使用它。Anthropic

设备连接以后，agent 有三种主要控制方式：MCP、命令行以及代码文件/API。

这个区分很关键。

MCP 可以理解成 agent 与工具、软件之间的通用连接协议；MHS 更像设备 driver 和 hardware abstraction layer。也就是说，MCP 可以成为 agent 进入 MHS 的一个入口，但 MHS 并不是“新版 MCP”。Anthropic

当操作很短时，agent 可以直接发命令。

当一个物理过程需要高速或者长时间连续运行时，让大模型每一步都在线思考反而很笨。于是 Claude 可以先观察设备、探索正确操作，然后把学到的策略写成一个 deterministic script。

Anthropic 举了激光对准的例子。Claude 先调整激光器，通过摄像头观察光斑怎样移动，再继续调整；理解控制关系之后，它把整个过程写进脚本，之后设备自己执行，模型不需要再在每个毫秒级动作之间推理。Anthropic

这揭示了一个非常重要的架构：

AI 不一定永远处于控制回路最里面。

更合理的结构可能是：

模型负责探索和决策。

然后生成一个普通、确定性的控制程序。

真正高速运行时，让传统软件接管。

物理世界 agent 的最终形态很可能大量采用这种“AI learning → deterministic execution”的混合方式。

Genentech 的案例：Claude 第一次尝试 pipetting 时就犯了一个非常典型的“没有物理常识”的错误

Genentech 用 MHS 做的是 BCA protein assay，也就是测量样品总蛋白浓度的经典实验。

这个过程需要三类设备协作：液体处理器负责精确移液，机械臂负责搬动实验板，microplate reader 测量样品吸光度。Anthropic

真正困难的地方不是理解实验步骤，而是液体本身具有不同物理性质。

普通水和 BSA 蛋白溶液的黏度不同。

如果 pipetting flow rate 太高，黏稠的蛋白溶液会产生大量气泡；气泡会占据 pipette 中的一部分体积，让真正转移的液体量偏小，也可能干扰 liquid-level sensor 和最终 optical reading。Anthropic

Genentech 第一次把标准实验 protocol 给 Claude 时，模型使用了非常通用的 liquid-handling 参数，并对水和黏稠 BSA 使用相同 flow rate。

结果 BSA 产生气泡，导致液体转移不准确。

这个失败非常有意思，因为 Claude 从符号层面完全“理解”实验，但没有足够强的 physical intuition。Anthropic

研究人员随后没有直接告诉 Claude 最优参数，而是给它一个实验任务：在专家定义的 flow-rate range 中自己测试。

Claude 每次改变 flow rate，实际向 plate 中转移带颜色液体，让 plate reader 测量结果，并与专家完成的 ground-truth transfer 比较。它用 RMSE 评价自己离目标有多远。

最后，Claude 对水选择约 140 µL/s，RMSE 约 0.016；对较黏的 BSA 选择约 10 µL/s，RMSE 约 0.181。Genentech 的 automation experts 判断这两个数对他们的 setup 是合理的。Anthropic

所以这里第一次出现真正的 closed loop：

AI 决定参数。

机器执行真实实验。

传感器产生现实数据。

AI 根据数据重新决定参数。

这已经不再是 synthetic simulation。

但 Claude 遇到气泡以后，又暴露了一个更深的问题：它会把物理错误当成软件错误

在实验过程中，Claude 遇到了 tip pickup failure 和 fluid detection error 等异常。

其中部分错误它能够自己恢复。

但碰到气泡时，模型最初采取的策略非常像一个只活在软件世界里的 agent：重试。

某个 well 失败以后，它换参数，再在同一个位置尝试一次。

问题是，对软件 API 来说 retry 往往是合理做法；对一管正在起泡的蛋白液体来说，反复搅动只会产生更多气泡。

于是系统反而越来越糟。Anthropic

研究人员最终必须明确告诉它，这是一个物理泡沫问题，不是 transient software failure；正确动作应该包括换到干净的 well，并减少 mixing cycles。

一旦 Claude 得到这个解释，它在后续实验中能够保持这条 context。Genentech 之后还把这些经验编码成 reusable liquid-handling skills，让模型遇到类似液体时可以直接使用更合理的默认参数。Anthropic

我认为这是全文非常有代表性的一段。

LLM 在软件领域遇到 error 的默认世界观，很多是：

重试。

换参数。

重新调用工具。

但物理世界具有 irreversibility。

你摔碎一个样品不能 retry。

试剂污染以后不能 Ctrl-Z。

培养细胞死了以后不能 restore checkpoint。

这意味着真正 physical agents 的安全性和软件 agents 会是完全不同的难题。

University of Washington 的案例反而更现实：很多实验员真正想自动化的，不是科学发现，而是“半夜四点起来换一块板”

David Baker 和 Sudarshan Pinglay 实验室的博士生 Zihao Song 提出了一个很典型的实验室痛点。

现在用 AI 设计一个新蛋白可以便宜得惊人。文章举的数量级是，设计类似 PETase 这样的候选蛋白，纯计算成本可能低至约 0.01 美元。Anthropic

但把这个候选真正放进实验室验证，可能仍然需要约 100 美元和一周人工。

而实验人员一次可能要验证大约1,000个 candidates。

所以 AI protein design 的 bottleneck 已经从“生成候选物”明显移动到真实实验 throughput。Anthropic

Song 描述的日常非常不 glamorous。

实验室只有一台某些关键仪器。

PCR 一次只能跑一块 plate。

每90分钟需要人工回来换下一块。

所以博士生甚至会凌晨4点起床去搬 plate。

监控也一样。设备散落在不同角落，HPLC 如果半夜报错、液体处理器突然 misfire，等研究员几个小时后发现，整份 sample 可能已经无法使用。Anthropic

传统 automated lab 可以解决这些问题，但价格和刚性都很高。工厂可以让一条产线一万次重复同一个 protocol；academic research 每年可能做几十种不同 protocol，其中一半是第一次运行，而且实验中间随时需要修改。

所以传统 automation engineering 的 ROI 很难成立。

Song 过去曾经花几周评估平台、找 vendor support、写 glue code，最后仍然放弃。使用 MHS 后，他把 6 台设备连接起来不到一周，其中还包含自己写 driver 的时间。Anthropic

一个很简单但很实用的应用，是让 Claude 替博士生“盯 PCR 曲线”

qPCR 在每个 cycle 中复制目标 DNA，并通过 fluorescent signal 显示复制量。

信号最初很弱，随后进入指数增长阶段，最终当 reagent 用尽后进入 plateau。

如果让 reaction 一直跑进 plateau，会扭曲 library，影响后续定量。

所以研究人员必须一直观察 amplification curve，在正确时刻停止。Anthropic

过去这个任务本质上要求一个博士生盯着仪器。

接入 MHS 后，agent 可以实时读取 curve。

当它判断 reaction 到达适当阶段时，可以询问研究员是否停止；获得确认以后，直接终止 reaction，并把设备切换到 4°C hold，防止 DNA 降解。Anthropic

这不是最炫目的 AI 能力。

但恰恰非常容易产生 ROI。

一个系统如果每天替几十名研究人员消灭这种“必须有人看着”的劳动，实验室的有效工作时间可以明显增加。

更进一步，Claude 开始协调机械臂和液体处理器，避免两台机器人撞在一起

Song 还把一台基于 Hugging Face LeRobot 的开源机械臂，与 liquid handler 通过 MHS 接在一起。

workflow 很简单。

Liquid handler 先把 reagent 加到 plate。

做完以后，机械臂把完成的 plate 拿走，再换进下一块新的 plate。

问题是两台机器必须严格协调，否则机械臂可能在 pipetting 尚未结束时伸进去，或者 liquid handler 在机械臂尚未离开时重新开始动作。Anthropic

Claude Code 负责协调两台设备。

只有上一阶段返回 completion signal，下一台设备才启动。

实验中 liquid handler 完成后，约 10 秒后 agent 触发机械臂下一动作；多轮测试里没有发生碰撞。研究人员本人只是在办公室电脑上监控整个过程。Anthropic

现在这还只是 proof of concept。

Song 自己也明确提醒，更复杂实验需要更高可靠性，持续数小时运行 agent 本身也有 inference compute cost，必须与节省的人力比较。

但真正吸引他的下一步是完整的 design-build-test-learn loop。

Agent 可以提出 protein designs。

自动安排 build 和 assay。

读取实验结果。

再根据真实数据生成下一轮设计。

这意味着实验室自己可以一轮又一轮自动产生 proprietary scientific data。Anthropic

Carnegie Mellon 做了一个更接近完整自动实验的案例：系统发现第一轮剂量曲线不好，自己扔掉，再跑第二轮

CMU 做的是 drug development 里非常常见的 dose-response serial dilution。

研究人员需要找到适当 concentration range。如果最高浓度太高，measurement 会 saturation；步长太小覆盖范围不足，步长太大又会错过真正的 transition region。

手工运行这一套实验可能需要多次迭代。即使已经有 robotic automation，建立 protocol 仍可能需要 automation engineer 花几周。Anthropic

CMU 的设备尤其能体现现实实验室为什么难自动化。

机械臂运行在一台电脑上，通过把 XML 文件扔进特定 directory 来控制。

Liquid handler 在另一台机器上，通过老式 Windows ActiveX/COM 接口。

Plate reader 在第三台电脑上，根本没有 API，只有 GUI。

另外还有 USB camera。Anthropic

MHS 把这些完全不同的控制方式统一成同一种 states 和 procedures。

团队从零编写 drivers 和 orchestration layer，让 Claude Opus 4.8 完整运行 protocol，只用了大约 8 小时；他们估计传统 vendor setup 通常需要数周。Anthropic

实验里使用的是一种安全的 colorimetric dye，并不是真实药物，但决策过程与真正的 dose-response 类似。

团队还故意制造六种异常：plate 缺失、plate 放反、reader 忙碌、camera 断开、device unreachable，以及 emergency stop 已被触发。

六种情况下，系统都在设备真正运动之前停止操作。Anthropic

然后真正运行实验。

第一轮 concentration range 最高达到 200 µg/mL。

Claude 看到结果以后判断拟合不够好，R² < 0.9，原因是高浓度区域发生 saturation。

它没有接受这个结果，而是自主丢弃这块 plate，把最高浓度降低到 100 µg/mL，重新运行完整实验。

第二轮得到 R² > 0.98 的可用曲线，过程中没有人类干预。Anthropic

这就是我认为 MHS 真正值得注意的能力边界。

它不是“让 Claude 帮我点击机器上的 Start”。

而是：

观察实验结果 → 判断结果不够好 → 修改实验参数 → 重跑真实实验 → 再评价结果。

这已经非常接近 autonomous experimentation 的基本闭环。

HHMI Janelia 的故事则展示了另一个瓶颈：一套顶级显微镜可能实际上是七个互不认识的软件拼起来的

Virginie Ruetten 在 Janelia 研究睡眠如何影响整个身体。

她使用年轻斑马鱼，因为斑马鱼体积小而且透明，可以通过 two-photon microscopy 同时观察脑、心脏、脊髓、肠道等不同组织的 cellular activity。Anthropic

但她的 microscope rig 并不是一台“机器”。

它是一间屋子。

里面有 femtosecond lasers、galvanometer mirrors、photomultiplier detectors、translation stages、camera 和 electrophysiology equipment。

这些东西来自不同厂商，甚至分别用 MATLAB、Python 和 C# 控制。Anthropic

过去她为了启动一次实验，需要按照固定顺序打开 7 个程序。

顺序错了甚至可能毁掉整个实验 session。

新增一个设备往往需要数天 integration。

接入 MHS 后，她新加一个用于观察 laser beam 的 camera，只需要几分钟。

开始实验也从7个独立步骤变成了 dashboard 上一次点击。Anthropic

更重要的是，MHS 把不同设备产生的数据统一写进 shared-memory state dictionary。

以前一个 MATLAB program 里的变量，Python 程序看不到；现在 camera image、stage position、heart signal 和 neural activity 都变成标准化数据流。

因此她可以写一次 frequency-analysis code，然后既用于分析斑马鱼心跳，也用于分析另一台设备产生的神经活动，而不必针对每个 vendor 重写。Anthropic

文章有一句很好的总结：过去工程工作分别积累在每个设备的独立 codebase 里，现在同一份工作可以在一个共享系统里复利。

更大的变化是，“ballistic experiment”开始变成 adaptive experiment

Ruetten 对传统实验用了一个很形象的概念：ballistic。

现在很多实验像发射炮弹。

开始之前决定全部参数。

然后启动。

等待几个小时。

结束以后才知道参数是否正确。Anthropic

但实际科学问题经常需要动态权衡。

例如 microscopy 中，扫描范围越大，可以覆盖更多脑区，但速度越慢；扫描范围越窄，可以获得更高 temporal resolution，却可能错过真正感兴趣的细胞。

传统做法必须在实验开始前选定一个 compromise。

Agentic microscopy 可以改变这件事。

先大范围扫描。

Agent 发现具有目标 oscillation 的细胞群。

然后立刻缩小区域、高速扫描。

实验参数由已经产生的数据反过来决定。Anthropic

Ruetten 已经用这种方式找到固定参数原本可能漏掉的一组 oscillatory cells，因此减少了重复实验以及所需动物数量。

而 MHS 设备层又可以直接限制最大 laser power，所以不必完全依赖 Claude 自己记得“不要把荧光分子照坏”。Anthropic

这其实是 autonomous science 很核心的一种价值：

不是机器跑实验更快。

而是实验本身开始变成实时 feedback policy。

QuEra 的案例是整篇文章里最惊人的：Claude 把一套专家写了几个月、成功率58%的控制脚本，优化到了99.3%

QuEra 使用 neutral atoms 做 quantum computing。

这类系统高度依赖 laser。

激光频率必须保持到大约 万亿分之一的精度；文章用一个很形象的尺度说明，相当于测量地球到月球的距离，误差只有一根头发宽。Anthropic

温度、振动或者空气压力稍微变化，都可能让 laser “unlock”。

而量子计算机如果正在运行一个持续几个小时的 error-corrected program，中途 laser unlock 可能毁掉整次 computation。Anthropic

传统上，这种问题需要经验丰富的技术人员处理。

一个人发现 unlock 后，要观察多个仪器、依次调节控制参数，并判断什么时候已经真正重新稳定。

通常需要 5–10 分钟。Anthropic

QuEra 早就尝试过自动化。

在 MHS 之前，一个由 laser engineer、software engineer、algorithm specialist 和 tester 组成的团队花了几个月编写 bespoke recovery script。

这个 script 基本就是把专家操作流程逐步写死。

最终成功率只有 58%，单次 recovery 大约 150 秒。Anthropic

原因并不难理解。

真实世界在你执行脚本期间仍然会变化。

脚本前面某一步已经调好，某个人推门进实验室造成温度或气压变化，那个步骤又可能失效；线性的流程只能重新从头开始。

QuEra 随后让 Claude 通过 MHS 接触同一套真实 laser system。

团队给它目标：写出一个 standalone Python script，第一次就把 laser relock，并保持30秒。Anthropic

然后人为制造各种扰动。

遮挡 laser beam。

断掉某些仪器电源模拟 surge。

把频率推离 target。

Claude 可以通过 MHS 读取仪器并移动真实控制器。Anthropic

最值得注意的是，它不是让一个 Claude 自己研究，而是建立了一个四 agent 自动实验团队

QuEra 把工作循环拆成四种角色，每轮都使用新的 Claude instance。

一个 agent 提出怎样让 recovery 更快、更可靠的 hypothesis。

一个负责修改 Python script。

一个把新 script 真正在 laser 上跑一次，并记录全过程。

最后一个阅读日志，再决定下一轮修改方向。Anthropic

这个 loop 整晚无人值守运行了数百轮。

我认为这篇文章真正重要的地方：AI for Science 的瓶颈正在从“模型能不能想”转向“现实世界能不能像 API 一样被调用”

下面是我的延伸判断，不是 Anthropic 的原文结论。

过去两年 AI for Science 里最吸睛的是 AlphaFold、protein generation、material discovery 和 virtual cell，因为这些都发生在 GPU 中。

但当 computational design 成本不断趋近于零以后，价值链会向下一层移动。

UW 那个数字很能说明问题：

计算上生成一个蛋白候选可以低至约 1美分。

真实实验却可能是 100美元 + 一周时间。Anthropic

如果每一美元 compute 可以产生十万条 hypothesis，而实验室一天只能验证100条，模型再聪明也不会让科学发现等比例加速。

所以真正决定 AI-for-science productivity 的指标可能越来越像：

每美元、每天可以完成多少个可信的真实 experiment-feedback loops。

这正是 MHS 的战略意义。

它并没有让显微镜更快，也没有让 PCR chemistry 更快。

它削掉的是现实实验之间大量人为的 coordination latency。

过去：

模型输出 hypothesis → 研究员读结果 → 写 protocol → automation engineer 写程序 → 人搬 plate → 等设备 → 看结果 → 再把数据上传给模型。

未来可能逐渐变成：

agent → MHS → instrument → sensor data → agent。

中间的人类 handoff 越少，scientific loop 越接近真正 machine-time。

我认为这对 life-science tools 产业尤其值得长期观察。Thermo Fisher、Danaher、Agilent、Waters、Tecan、QIAGEN 这些公司的设备过去很大一部分粘性来自独立软件生态和复杂 workflow。如果 MHS、SiLA、OPC-UA 等通用 agent interface 最终成功，设备的软件差异可能部分被抽象掉，客户越来越关心的是仪器本身的 reliability、precision、throughput 和 service，而不是 proprietary UI。反过来，最早原生支持 agent control、提供高质量 telemetry 和 robust safety API 的设备商，也可能因为更容易进入 autonomous lab 而获得新的竞争优势。这里还处于非常早期阶段，不能据此判断传统仪器软件护城河已经消失。

更值得注意的是 QuEra 的案例，它揭示了一个更大的 AI 经济学变化。Claude 真正超过专家的地方，并不是拥有比 laser engineer 更强的物理理论，而是它可以在16小时里连续做 363个真实实验，每次都做一个人类嫌太麻烦的完整测量，再不断搜索参数空间。Anthropic

这意味着一旦 physical automation 足够成熟，AI 的一个巨大优势会从“思考速度”扩展成 empirical iteration speed。

过去一个研究员一天只能试十次。

未来 agent 可以试一千次。

它不需要第一次就比人类聪明。

只要现实世界允许它快速、廉价、安全地得到反馈，它就可以靠搜索找到人类靠经验无法轻易发现的解。

所以这篇文章最值得记住的并不是“Claude 可以控制机械臂”。

更重要的是另一件事：

AI 开始获得了产生自己下一批真实训练数据的手。

如果 MCP 让模型可以调用软件，那么 MHS 想做的是让它可以调用实验。等 hypothesis generation、自动 researcher、physical instruments 和 verifier 真正连成一条闭环以后，AI for Science 才可能从“AI 给科学家提供建议”，走到“AI 与现实世界持续对话”。

而那时科学研究真正稀缺的资源，也许不再只是 GPU 或顶尖研究员，而是那些能够被机器安全、快速、重复访问的 reality interfaces。Anthropic
