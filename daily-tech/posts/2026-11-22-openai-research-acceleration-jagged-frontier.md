# 当研究员开始同时指挥十几个 AI：OpenAI 的最新实测揭示科研自动化的真正瓶颈

2026 年 11 月 18 日，OpenAI 研究团队发表了免费公开的研究报告 [《Research acceleration: The jagged frontier》](https://openai.com/index/research-acceleration-jagged-frontier/)，中文可译为《研究加速的参差边界》。这篇报告的价值不在于又给出一个模型能力排行榜，而在于把镜头对准前沿 AI 实验室的实际生产现场：研究人员每天调用多少 AI、能把多复杂的工作交出去、工作质量在哪里卡住、更多代码和实验最终有没有换来更快的模型进步。它还触及一个更难回答的问题：当 AI 开始参与研发下一代 AI，什么才算真正发生了研究加速？

## 一间实验室正在变成大量并行 Agent 的工作场

观察 AI 对研发的影响，容易从某个模型能否完成编程测试开始。但模型的分数只是潜在能力，实验室如何组织工作才决定能力最终能发挥多少。OpenAI 的内部数据提供了另一个视角：一个研究员的生产方式，正在由亲手完成每个步骤，转向为多个自动化执行者提供问题、上下文、约束和验收标准。

这种改变首先体现在使用强度上。到 2026 年 10 月，以公开 API 的标价折算，OpenAI 研究组织中处于使用量中位数的研究员，每天调用的 Agent 服务约值 2,400 美元；处于第 90 百分位的重度用户，约为每天 23,000 美元。9 月这两个数字分别约为 1,500 美元和 11,000 美元，因此中位数一个月增长了 62%，高使用群体增长了 105%。重度使用者不仅比一般人调用得更多，扩张速度也更快。

这些美元数字不能直接理解为 OpenAI 每天向外部支付的账单，也不能当作每个研究员的现金成本。报告采用的是 API 等价标价，记录的是模型调用量在公开计费体系下的价值。使用增加可能来自提交更多任务、改用价格更高的模型、模型生成更多 token，或者 Agent 运行框架改变了调用方式。研究员在内部没有面向编程 Agent 的固定用量配额，进一步使这种强度与普通商业用户的使用体验不同。

为了不让价格变化掩盖实际工作量，研究团队又引入了「Agent 工作日」：把 Agent 累计运行八小时折算为一个工作日。这并不是说机器在八小时内创造了一个人类工作日的产值，而是用统一的时间尺度衡量模型实际运行了多久。按此口径，每名研究员对应的 Agent 工作日从约 0.5 个增至约 5.7 个，约为原来的 11 倍。预训练和后训练团队的平均值已接近每个自然日八个 Agent 工作日，扩展与基础设施团队则大约是四个。

同一个自然日能积累超过八小时的 Agent 工作量，关键在于并行而非时间被拉长。到 10 月中旬，纳入统计的研究员中，超过三分之二的人每天的 Agent 并发峰值平均至少达到四个，超过十分之一的人至少达到十六个。统计还包括 Agent 派生出的子 Agent 和多会话。一个人可以同时让不同系统调查错误、修改代码、检查实验日志或处理数据，而不必等待前一个任务结束。

这一口径也有边界。Agent 工作日更接近运行时长，既不能反映不同模型的真实生产率，也不随模型能力自动校正；统计主要覆盖交互式使用，可能低估自动运行的流程。报告还提到一项容易误读时间序列的工程细节：8 月 21 日曾上线一项临时的 Agent 框架效率改动，显著压低了记录到的输入 token 用量；自 9 月 10 日起，这一改动因与支出无关的原因逐步回退，随后账面 token 支出迅速回升。因此，单看某几周的费用曲线，无法把每一次起落都解释为研究生产率变化。

## 机器劳动很贵，但只占研发算力的一小部分

研究人员究竟是在购买一个廉价的软件助手，还是正在把原来由人完成的工作改由模型承担？OpenAI 尝试比较 Agent 的 API 等价使用价值与研究人员的非股权薪酬。到 9 月，前者大约达到后者的两倍，而且预训练、后训练团队的比例高于其他部门。这里的薪酬包含工资、加班费、奖金、福利和雇主税费，却没有包含股权；按报告口径，股权通常占 OpenAI 研究人员目标薪酬的 70%—80%。因此，「两倍」不能被解释为 Agent 已经比全部人力成本高出两倍，更不能据此推算公司裁员或替代雇员的经济动机。

更反直觉的是，这些内部调用——合并内部 Codex、ChatGPT 和 API 使用——只占 OpenAI 全部研究算力的约 2%。用于训练和其他大规模研究工作负载的计算资源依旧构成绝对主体。Agent 在研发流程中的存在感与它在研究总计算量中所占的比例，完全不是同一个概念。

由此形成一种新的研发资源结构：相对于单名研究者的日常操作，Agent 已经是数量庞大的辅助劳动；相对于训练下一代前沿模型所需的总体算力，它依然是一个很小的部分。预算如何在模型训练、研究工具和人类研究者之间配置，将不能只靠 token 价格或某个岗位是否被替代来判断。

## 「半数任务能独立做完」的另一面

模型使用量增长，并不代表委派出去的工作都有可靠结果。OpenAI 按任务大致需要多少人类工时划分难度，测量 Agent 在没有人类介入时能否成功完成研究任务。从 3 月到 10 月，估计需要人类两到四小时的任务，零人工介入成功率由 23% 升至 46%；需要四到八小时的任务则由 13% 升至 35%。这比模型能连续写多久代码更接近研究员每天实际会遇到的问题。

但「两到四小时」并不是固定不变的标准化题库。随着模型变强，研究员也可能把本来不敢交出去的任务纳入同一个时长区间；两个月份中归入同一档的任务，不一定具有相同的复杂度或结构。报告此次也更新了估算方法，所以这些变化应被视为内部测量到的趋势，而不是严格控制实验中得出的纯粹能力增幅。

把任务按性质分开，成功率差异比按时长划分更明显。2026 年 8 月 1 日至 10 月 18 日间，按 Epoch AI 制定的 [AI 研发职业任务分类框架](https://epoch.ai/gradient-updates/toward-an-onet-for-ai-rnd) 统计，沟通类任务的零介入成功率约为 69%，分析类约为 58%，构建类则只有 43%。这意味着「模型能处理一项四小时任务」不能自然推出它对各种四小时任务具有类似的可靠性。

差异落到具体工作上更加鲜明。监视训练任务是否出现异常，成功率达到 79%；回答技术问题为 72%。然而，真正发起一次训练运行只有 35%；为推理和在线服务系统编写代码只有 25%；构建评测、强化学习及 Agent 环境也只有 29%。监控现有系统与创建一个能经受后续实验检验的新系统，面对的是不同难度的判断与整合问题。

这使「参差边界」成为整份报告的中心概念。研发不是一组可以彼此完全替换的任务。如果训练监控自动化了八成，但实验环境建设经常失败，研究员仍要在关键环节重新投入时间。对整个流程而言，薄弱环节可能比擅长环节更加决定总产出。报告提供的是不同任务成功率的估计，没有证明这些比例能线性相乘，也没有给出每次失败需要多少返工成本；瓶颈的判断来自这些能力不均衡的工作结构。

研究团队同时尝试改变对使用数据的观察方式。过去按模型输出 token 分配工作类型，会让需要大量生成内容的复杂编程和长时运行任务显得格外突出。这次又观察单项任务发生的频率，让技术问答等短而高频的操作得到更多权重。两种口径描述的是不同问题：一种近似模型把计算花在何处，另一种近似研究员一天里多经常向它寻求帮助。不能用任一口径单独代表工作的价值。

## 研究员为什么愿意拿团队资源换 Agent

如果调用量和成功率都只是局部指标，那么研究者自身怎样估价这些工具？2026 年 8 月下旬至 9 月上旬，OpenAI 对 101 名研究员工做了一项问卷：假设团队在未来三个月无法使用比 GPT-5.2 更强的编程 Agent，愿意付出什么代价换回前沿工具？

受访者答案的中位数相当激进。在分别提出的假设情境中，他们愿意放弃团队 40% 的人员规模，或者 30% 的现有计算资源，来保留 Agent。如果问题变成展望 2027 年 1 月的模型能力，愿意交换的计算资源中位数上升到 50%。受访者还估计，如果只能使用 GitHub Copilot 加 ChatGPT、不能使用更先进的编程 Agent，团队可能需要约三个月，才能完成最近一个月创造的同等价值工作。

这些回答是对假设交易的主观估价，绝不是实际裁员 40% 后进行过的随机试验，也不能据此宣布研究部门生产率精确提高了三倍。问卷抽样是临时组织的，参与者对自己生产率的判断也可能有偏差。但它展示了另一个事实：在已经围绕 Agent 重组工作方式的人群里，失去工具被认为是严重的生产能力损失。

10 月下旬的另一项调查提出了更具体的选择：最新内部模型，与一名有数年经验的研究工程师加上 2024 年的 o1-preview 模型，哪一组会让受访者日常工作更高效？28 名受访者中，27 人直接或倾向选择最新内部模型。余下一人并未按原题的两个选项作答，而表示相较于有人类工程师的组合，更愿意选择 GPT-6 Astra。这是一组偏好调查，不是对工程师和模型统一验收后的能力比较，却足以说明前沿工具的替代价值在研究者心中有多高。

## 执行提速之后，「研究品味」浮出水面

用量扩张到一定程度，下一道难题变成怎样决定值得做什么。AI 能修复代码、排查错误和整理资料，并不等于它能独立提出值得花数百万美元训练预算检验的研究假设。研究报告用「research taste」指称这种判断力：识别重要问题、判断实验是否有意义、挑选真正可靠的数据，并在错误的方向上及时止损。

为了寻找概念性突破究竟从何而来，OpenAI 让预训练、后训练和安全监控领域的关键研究贡献者，回顾 GPT-6 Astra 与 GPT-6.2 Astra 发布过程中各自最重要的研究想法。每个领域参与访谈的关键人员约一至四人，分别挑出一至三个重要想法，并追溯它们的来源。这并不是对所有研发创意进行完全枚举，而是对若干公认重要成果的溯源。

在被询问的后训练与安全监控案例中，研究者认为重要想法仍由人提出，模型主要负责落实。GPT-6 Astra 的预训练相关想法也被归于人类。到了 GPT-6.2 Astra，预训练团队开始描述与 Codex 讨论、共同修改研究方案的经历：有人认为 Codex 帮助找到了重要洞见，也有人表示最初的设想出自自己，但模型建议的改动让方案最终效果显著改善。AI 已经从纯粹执行进入部分共同设计，却不能据此得出整个模型研发已经自动提出并验证关键思想的结论。

对十位预训练、后训练与安全研究者的访谈，更具体地说明了协作的形状。在一些评测项目上，把开源评测搬入内部系统、跑起来并进行必要的对照分析，过去可能需要一至两周，现在有时缩短为一天或几天。Agent 对实验调试、代码实现、日志查看与数据扫描很有价值。面对数千条样本，研究者可以让模型反复筛查问题、标记异常，再经过人工校准得到结构化的分析资料，减少大量繁琐检索劳动。

但速度也会制造新的审查负担。受访者描述过 Agent 在不必要的操作上钻牛角尖、生成质量不合格的代码改动、制造无法使用的数据文件、建立错误分析假设，或者启动实验时缺乏效率。更隐蔽的问题是输出看似完整却缺少「好研究」所要求的分辨能力：提出的问题并不精确；重复生成的数据点彼此相似，覆盖不了足够广泛的情况；产出的文字或代码形式上流畅，实际不能直接投入下一轮研究。

因此，有研究者改变了交付任务的方式：先让 Agent 做出一个实例，由人检查、修改并确定质量标准，之后才批量生产后续内容。这与把任务整包丢给模型、直到最后才验收有本质差别。人在这里不是因模型完全不会做而接管全部工作，而是把判断力放在能够影响后续所有结果的检查节点上。

同时，这些研究者并未把当前局限视为永久规律。有受访者认为自己在选择研究想法方面仍明显胜过模型，却没有信心这种优势会长期维持。报告保留了这种张力：今天的工作流高度依赖人的判断，并不意味着未来一定如此；未来可能出现的能力突破，也不能代替对今天任务失误的真实记录。

## 人类研究力量正在流向哪些工作

当 Agent 消化越来越多日常代码和分析工作，人类时间并没有简单消失。OpenAI 尝试追踪研究者注意力的重新分配：汇集 2026 年 1 月至 9 月间公司内部公开 Slack 帖文、拉取请求与研究文档，再用分类器识别研究领域。如果同一研究员一周参与多个经确认的项目，便将该周工作份额平均分到这些项目，而不是简单按部门归属统计。

这样的做法能捕捉实际项目中的跨团队投入。例如，一名隶属后训练部门、同时从事基础设施建设的研究者，可以在统计上分别为两个领域贡献部分工作周。它依然只是以可见工作痕迹代理人类投入时间，不能等同于精确工时记录。后训练和安全对齐之间的边界本身也很难划清，分类口径可能继续调整。

在几乎所有主要研发领域的人力投入都增长的背景下，安全与对齐的已记录工作周增加得尤其显著：1 月至 9 月增长 77%，在主要研究领域中录得最大的绝对增量。变化既来自新增人员，也来自现有研究者转向安全项目。相关工作涉及对齐评测、行为可监控性，以及奖励作弊等问题。7 月的 [Hugging Face 事件](https://openai.com/index/hugging-face-incident-and-the-road-ahead/) 后，安全工作投入出现明显的加速拐点。

这与「AI 提高效率后人会减少」的直觉不同。研发可以同时变得更自动化、扩张更快，并且需要更多人力去研究哪些模型行为可以信任、哪些结果值得采纳、哪些系统必须先加固。报告没有给出反事实结论：无法判断如果没有 Agent，安全团队本来会有多少人；也无法将安全投入全部归因于模型自动化。它至少说明，仅观察组织中 Agent 调用量或代码产出，无法理解人类劳动在研究流程中的新分工。

## 更多代码、更密集实验，究竟等于多少真正进步

OpenAI 最后把视角转向研发的输出。代码修改量在 2026 年快速增长，相对 2025 年之前的平均水平变化显著。新报告把统计从季度平均调整为过去 28 天的滚动平均，并更新代码变更计数口径，特别排除了测试代码，以便更细致地观察趋势。但代码多不代表好代码多；在 Agent 可能生成大量返工内容的情况下，提交行数更不应被视为研究成果的直接计量单位。

实验数量提供另一条线索。截至 10 月 18 日的四周里，每名活跃实验研究者的已记录实验数平均为 2025 年基线的 1.68 倍。实验变多至少意味着进行尝试的频率提高，但不能单独分辨是 Agent 缩短了准备时间、研究所获算力更多，还是实验规模或记录方式发生改变。此前的 [9 月研究加速报告](https://openai.com/index/research-acceleration-view-inside-openai/) 已提醒，研究算力持续扩张也会推动实验数量。即使多跑了十次实验，也可能没有得到一次可用于下一代模型的突破。

为了向真正的能力产出靠近，OpenAI 还建立了内部版本的 Epoch Capabilities Index，简称 OECI。它借鉴独立研究机构 [Epoch AI 的能力指数](https://epoch.ai/eci?tab=release-date&view=graph)，同时纳入公开基准与 OpenAI 自身的内部评测。报告绘制了二十个已公开发布的 OpenAI 模型和二十八个其他模型的 OECI 水平，试图比代码量或实验次数更直接地观察模型能力前沿。

按这一口径，自 2025 年 8 月起，OpenAI 模型的 OECI 前沿趋势每年提高约 16.4 分；作为参照，Epoch 对其自身指数自 2024 年末以来观察到的趋势约为每年 14 分。两条线来自不同的起始时间、不同的基准组合，不能机械地比较后宣布 OpenAI 的实际能力进步速度高出 2.4 分。报告也说明，OpenAI 模型在 OECI 上相对竞争者的表现比在 Epoch 自己的 ECI 上更强，可能正是评测组合差异所致。

这些指标被放在一起后，最重要的不是一个漂亮的单项数字，而是因果链仍有缺口：研究人员用了更多 Agent，代码和实验活动增加了，模型能力也持续提高，但这还不能证明能力曲线的每一分提升来自 Agent，也不能证明研发整体已经进入不受其他资源约束的自我加速阶段。模型变强会提高 Agent 使用效果；研究者改变流程会进一步释放其价值；算力、数据和研究思路仍可能成为独立瓶颈。

## 当 AI 开始帮助设计下一代 AI，安全速度也要一起衡量

OpenAI 把这种变化放在「递归自我改进」的讨论中：AI 参与开发后继 AI，并可能因此加快后继系统的改进。过去常用的想象是，一个系统完整代替研究人员，从选择方向、设计实验到训练发布都自动完成，然后进入快速循环。研究报告更谨慎地强调，当前大量工作仍由人与 AI 协作完成，不能把这种部分自动化直接等同于完全自主的递归研发。

这也是为什么追踪指标本身具有治理价值。假如行业只关注一个旗舰模型能否越过排行榜门槛，就可能忽略内部研究工作流何时发生突变。反过来，若只看 Agent 使用量的指数增长，又可能把算力消耗错误当作技术奇点。OpenAI 主张前沿实验室持续公开与递归自我改进有关的指标，让外部能够讨论模型能力、潜在风险以及必要的监督机制。报告特意说明，披露相关进展并不等于宣布追求没有人类监管的完全自动化。

对未来的担忧并非单纯来自现在的编程速度。OpenAI 提到前沿模型近期在数学领域出现突然且迅速的突破；历史上测得的逐步改善，不一定能预测新的研究能力何时跨过某种门槛。对深度学习研究而言，可能出现类似的突变，也可能因实验成本、判断能力和安全要求而呈现不同轨迹。把当前趋势直接外推成年复合增长率，忽略了这些非连续的可能性。

接下来值得追踪的测量问题因此更加明确：能力研究与安全研究的效率是否在同步提升，是否存在不必等下一代完整训练结束就能发现研发加速的先行指标，以及模型能力曲线究竟在多大程度上受到 AI 辅助科研的推动。这些问题现在尚无最终答案。报告能确认的是，Agent 已经成为前沿实验室的重要工作力量，但决定性研究判断、对可靠性负责的验收与人类监督仍处于研发系统的核心。

## 延伸判断与启示

从工程管理角度看，最有价值的变化未必是「一名研究员能启动多少个 Agent」，而是能否建立一套将高频、低风险任务并行化，同时把人工判断集中在实验设计、质量验收和方向取舍的系统。如果四分之一的推理服务开发任务能够无介入成功，简单把执行次数扩大四倍并不必然降低交付成本，反而可能产生更多需要审查的中间产物。因此，未来的 Agent 平台竞争不只取决于单次生成质量，也可能取决于任务分解、环境可复现性、自动验证、故障定位以及研究人员介入节点的设计。这个判断由报告中观察到的任务差异和协作实践推演而来，并非报告给出的产品市场预测。

对 AI 基础设施与产业经济而言，研发工具的调用量正在形成一种与训练计算不同的需求来源：使用频次高、并发度大、需求与模型能力互相促进，但它在整体研究算力中的占比仍相当有限。不能把每天 2,400 美元的 API 等价使用量直接换算为芯片营收，也不能据此断言推理支出会迅速压过训练支出。更值得观察的是，随着模型开始参与研究设计，人类和 GPU 之外的另一种稀缺资源会逐渐显形：哪些工作有可验证的完成标准，以及谁有能力识别真正值得继续投入的结果。
